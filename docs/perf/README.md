# Phase 0 パフォーマンス計測

Issue #244 の計測基盤です。性能改善は含みません。親 Issue #243 のベースラインは、この文書と `docs/perf/results/` を参照します。

## 構成

| 場所 | 役割 |
| --- | --- |
| `src/perf/datasetSpec.ts` | S / M / L と XL の件数、検証 |
| `src/perf/generateSyntheticDataset.ts` | 固定シードの合成データ |
| `src/perf/summarizeSamples.ts` | 中央値、最小、最大、不偏標準偏差。20 試行以上のときだけ p95 |
| `src/perf/probe.ts` | 本番経路に足す任意の計測。フラグが無いときは処理結果を変えない |
| `perf/baseline.spec.ts` | 専用ブラウザコンテキストでの計測 |
| `playwright.perf.config.ts` | 通常の E2E とは別の Playwright 設定 |
| `docs/perf/results/` | 機械可読な計測結果 |

合成データの生成処理は、通常のアプリケーション起動には入っていません。計測用 Playwright が本番ビルドを開いたあと、そのコンテキストの IndexedDB にだけ投入します。

## 実行

```bash
npm run perf:baseline
```

Phase 1 を再計測するときは、Phase 0 の `docs/perf/results` を上書きしないよう出力先を指定します。

```bash
PERF_RESULTS_DIR=docs/perf/results/phase1 npm run perf:baseline
```

```powershell
$env:PERF_RESULTS_DIR = "docs/perf/results/phase1"
npm run perf:baseline
Remove-Item Env:PERF_RESULTS_DIR
```

これは `npm run build` のあと、`vite preview`（port 4179）に対して `playwright.perf.config.ts` を実行します。`npm run test:e2e` には含まれません。結果の出力先は `PERF_RESULTS_DIR` で変えられます。未指定時は `docs/perf/results` です。`writeResult` は同じファイル名を上書きし、`measuredSourceCommit` がある結果は `archiveLegacyResult` で退避しません。JSON の `purpose` は計測スクリプトの既存ラベル `phase-0-baseline` のままです。

## 指標

時間の単位はミリ秒です。完了待ちに固定の sleep は使っていません。

| 指標 | 開始 | 終了 |
| --- | --- | --- |
| 起動 | navigation の `startTime` | 「概念を追加」が有効になり、概念・クイズ問題・学習ログの読み取りがそれぞれ 1 回以上記録され、最新の学習ログ読み取り以降に BKT・クイズ統計・混同ペアが各 1 回以上完了した時点。その時点のプローブ件数だけを集計し、それより後の試料は含めない。ログ読み取り前に打ち切った `modelCalls` 0 は完了にしない。DOM が変わらなくても requestAnimationFrame で確認する |
| 画面遷移 | クリック直前の `performance.now()` | 遷移先の見出しが表示された時点 |
| 概念の登録・編集 | 「保存」クリック | 編集ダイアログが閉じた時点 |
| 概念の削除 | 確認ダイアログの「削除」クリック | 対象タイトルが一覧から消えた時点 |
| 検索 | 検索語を入力した時点 | 対象タイトルが表示された時点。製品の 200ms デバウンスを含む |
| IndexedDB | `getAllConcepts` / `getQuizQuestions` / `getQuizAttemptLogs` の開始 | それぞれの return |
| 学習モデル | BKT mastery map、クイズ統計、混同ペアの既存関数の開始 | それぞれの return |
| DOM | 起動完了時点の要素数 | |
| Long Task | navigation の `startTime` 以上、起動完了時刻未満に開始した `longtask` | |
| メモリ | `performance.measureUserAgentSpecificMemory` | 使えない場合は未計測 |
| React 描画 | 通常の本番ビルドでは未計測 | Profiler 用ビルドの数値とは混ぜない |
| バンドル | `dist/index.html` が参照する JS を初期チャンク、その他の JS を遅延チャンク | |

## コールドとウォーム

- コールド: 新しいブラウザコンテキストに合成データを入れたあと、HTTP キャッシュ、Cache Storage、Service Worker 登録を消してから読み込む。IndexedDB の合成データは残す。
- ウォーム: その直後の `reload`。HTTP キャッシュと IndexedDB は保持する。Service Worker がこの再読み込みを制御するとは限らない。
- ウォームアップ試行は、上の手順を 1 回実行して破棄する。S の集計試行は 5、M は 3。L は実行できた場合 1 試行。
- p95 は 20 試行未満では記録しない。
- CRUD は各試行のあと、追加した概念を削除し、概念・クイズ問題・文脈カードを合成データで put し直してから reload する。概念削除は隣接関係と参照先問題も書き換えるため、削除した概念だけを戻しても次の試行と同じ状態にはならない。
- データ生成と IndexedDB 投入の時間は、起動・操作の時間に含めない。

## 安全性

計測は Playwright の新しいブラウザコンテキストだけで行います。開発中の通常プロファイルや、利用中の IndexedDB は開きません。Private Sync への接続処理は計測手順に入れていません。コンテキストは計測のたびに閉じます。

## 比較方法

後続 Phase では、同じ seed、同じ規模、同じ `schemaVersion: 1` の結果 JSON を残し、指標ごとの `median` を比べます。`trials` の個々の値も残しているので、分布ごと比較できます。本番ビルドの結果と、React Profiler 用ビルドの結果は別フィールドのまま比較しません。メモリ API 以外の値をメモリの代替にしないでください。

試行数が少ない指標は、差がばらつきの範囲内なら改善とは判断しません。XL は回帰判定に使いません。

## 解釈上の注意

- 画面遷移時間には、Playwright がクリックを届ける時間と、見出し出現までの描画が含まれる。
- 検索時間には 200ms のデバウンスが含まれる。
- IndexedDB の duration は呼び出し時間の合計である。並行して読むと、壁時計時間より長くなる。
- IndexedDB と学習モデルの時間は、プローブの記録処理をわずかに含む。プローブが無いときは `performance.now()` を呼ばず、処理内容と計算式は変えていない。
- Long Task は navigation の `startTime` 以上、起動完了時刻未満に開始したものだけを数える。完了より後に始まったタスクは含めない。
- 起動時の学習モデル時間は、概念画面の BKT・統計・混同までである。Data Lab を開いたときの追加計算は画面遷移時間の側に現れる。
- 合成データの分布は実利用の分布と同じではない。

`docs/perf/results/superseded/` にある JSON は、試行間の復元が不十分だった計測か、それ以前の記録である。前後比較には使わない。有効なベースラインは `docs/perf/results/` 直下で、`measuredSourceCommit` を持つファイルだけである。

## 結果

2026-11-25 に、commit `2f28abd011128bed8c9de57de7ae46009fd18c4f`（tree `e758dee7c5d55e0b690799ef1c79df4cc0c44f2b`）を同じ端末で計測した。結果 JSON の `measuredSourceCommit` と `measuredSourceTree` はこの値で、`contentMatchesHead` は true である。計測対象パスの `git diff HEAD` と未追跡ファイルは空だった。`git status` は `vite.config.js` を表示したが、内容差分ではないため計測は拒否していない。結果を記録する commit はこれより後なので、`resultsCommit` は null のままである。

前回の `79741cf` から変えた計測方法は、Long Task の未通知分を `takeRecords()` で一度だけ足すことだけである。起動、画面遷移、検索、CRUD の集め方は同じなので、それらの差はこのセッションのばらつきである。比較に使う値は今回の JSON である。

画面遷移、検索、CRUD は、各操作の前に合成データとの一致を確認し、操作のあと全ストアを入れ直してから reload している。S は操作 3 試行、M も 3 試行。これらの中央値を後続 Phase の比較に使う。

起動完了は、概念・問題・ログの読み取りに加え、最新のログ読み取り以降の BKT・クイズ統計・混同ペアが揃った時点である。Phase 1 の試行はすべて `modelCalls` が 3 で、0 件の試行は無い。旧実装はログ到着前の 1 周と到着後の 1 周が残り、ウォームでは完了前に追加の 1 回が入る試行がある。回数の減少は再計算をやめたことと一致する。学習モデル時間の中央値は減っていない。時間短縮の主張はしない。

IndexedDB は概念・問題・ログが各 1 回になり、レコード数は問題とログの余分な 1 回分が消えた分と一致する。M と L の起動時間の低下は、この読み取り減少と並んでいる。S の起動時間差は試行のばらつきの範囲で、改善とは判断しない。

2026-11-25 の Intel 端末で記録した概念画面への復帰時間と概念編集時間は、この再計測の比較表には入れない。試行が少なく、端末も違うため、操作が速くなったとは判断しない。
